# storage/

Async SQLAlchemy 2.0. Tables, repository functions, session helpers, and
the row ↔ domain adapter pair.

See [`../../../CLAUDE.md`](../../../CLAUDE.md) for project-wide rules
(including the `LLAMA_MODEL_PATH`-required-for-alembic gotcha and the
alembic autogenerate workflow, which are cross-cutting and stay at root).

## What's here

- `tables.py` — `Base` (with the `pk_/fk_/uq_/ix_/ck_` naming convention
  and `schema="invoice_importer"`) plus `AddressRow`, `VendorRow`,
  `InvoiceRow`, `InvoiceLineItemRow`. `InvoiceRow.content_hash` is the
  idempotency key; `(vendor_id, invoice_number)` is uniquely constrained.
- `db.py` — `make_engine`, `make_session_factory`, and
  `transactional_session` (async context manager: commit on clean exit,
  rollback on exception).
- `repository.py` — `get_or_create_vendor`, `save_invoice`,
  `get_invoice_by_id`, `list_invoices_for_vendor`. None of them commit.
- `adapters.py` — `to_*_row` / `from_*_row` for `Address`, `Vendor`,
  `InvoiceLineItem`, `Invoice`. Pure functions; no I/O.

## Invariants

- **Repository functions never commit.** `transactional_session` in
  `db.py` is the only commit/rollback boundary. `save_invoice` calls
  `flush()` to surface `IntegrityError` (turned into
  `DuplicateInvoiceError`) and to populate generated PKs, but never
  `commit()`. Preserve this split — repository code must be composable
  inside a larger unit of work.
- **Sessions use `expire_on_commit=False`.** Set on the factory in
  `make_session_factory`. Eager-load relationships with `joinedload` /
  `selectinload` (see `get_invoice_by_id` for the canonical pattern with
  joined `vendor.address` and selectin `line_items`). Never rely on
  lazy-loading after commit — `expire_on_commit=False` keeps attributes,
  but new traversals after commit will still hit a closed session.
- **Postgres schema namespace = `invoice_importer`.** Set on
  `Base.metadata`. The schema must exist in the target database before
  `alembic upgrade` will succeed — this is a one-time DBA step, not part
  of the migration chain.
- **Naming convention is on `Base.metadata`, not per-constraint.**
  `pk_<table>`, `fk_<table>_<col>_<ref>`, `uq_<table>_<col>`,
  `ix_<label>`, `ck_<table>_<name>`. Autogenerated migrations use it.
  Don't override it on a single column or you'll get inconsistent
  constraint names across migrations.
- **`asyncpg` in production, `aiosqlite` for in-memory tests.** The
  driver is encoded in the URL (`postgresql+asyncpg://`,
  `sqlite+aiosqlite://`). Code paths must work on both — see
  `tests/conftest.py`.
- **`save_invoice` is idempotent on content hash.** SHA-256 of the source
  bytes. Re-importing the exact same file raises `DuplicateContentError`
  before any rows are inserted; a different file from the same vendor
  with a clashing `(vendor, invoice_number)` raises
  `DuplicateInvoiceError` after the flush.

## Extension points

New table: add the `Mapped[...]` model in `tables.py`, the row ↔ domain
adapter pair in `adapters.py`, and any repository function in
`repository.py`. Then autogenerate a migration and review it (the alembic
workflow itself is documented at root).

New query: add an `async def` to `repository.py`. Take an `AsyncSession`
as the first arg (caller owns the transaction); use `joinedload` for
many-to-one and `selectinload` for one-to-many. Return domain objects via
`from_*_row`, not rows.

## Gotchas

- **`repository.py` does `from invoice_importer.storage.adapters import *`.**
  Wildcard. New adapters get picked up implicitly; renaming an existing
  one will silently break `repository.py` at runtime if you forget to
  update both. Worth tightening, but not a drive-by fix.
- **`save_invoice` calls `await session.rollback()` on `IntegrityError`
  before re-raising.** That ends the surrounding transaction, so the
  `transactional_session` exit will see a closed transaction and skip
  its own rollback. Intentional — but means partial state in the same
  transaction before the conflict is also discarded.
- **`InvoiceLineItemRow` has no FK index of its own** beyond what's
  declared (`index=True` on `invoice_id`). The `UniqueConstraint` on
  `(invoice_id, line_number)` covers ordered lookup; don't add a second
  index thinking it's missing.
- **`expire_on_commit=False` is set on the factory, not per-session.**
  If you build a session some other way (e.g. directly via `AsyncSession(engine)`),
  you'll re-introduce the default `True` and break every caller that
  reads attributes after commit.
